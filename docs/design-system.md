# Quantas GUI design system

The interface should make complex scientific data easier to read without
competing with it. Quantas Dark and Quantas Light share the same structure,
spacing and semantic colours; System mode follows the browser preference.

## Main colours

- background: `#071522`;
- deep background: `#04101a`;
- structural blue: `#69bce8`;
- strong blue: `#2994d1`;
- scientific orange: `#ed8a28`;
- success: `#50c6a9`;
- warning: `#f0b75a`;
- error: `#f06c75`.

Base tokens live in `assets/00_tokens.css`. Theme, text scale, reduced motion
and table density are defined in `assets/60_settings.css`. Result Explorer
rules remain isolated in `assets/40_results.css`.

## Visual priorities

1. Scientific figures and tables remain the main content.
2. Warnings and errors are obvious without becoming theatrical.
3. Similar controls keep the same hierarchy across workflows.
4. Inspection remains usable on tablets and phones, while complex matrices or
   setup tasks may still recommend a larger screen.
5. Motion respects `prefers-reduced-motion`.
6. Toolbars adapt to narrow spaces without hiding the scientific context.

## Renderer controls

Plot and table controls are shared components. They include table or figure
selection, page size, colormap, hover mode, spherical projection, message
filters and trace visibility.

A new option belongs here only when it changes presentation. Any physical or
numerical transformation must go through `quantas.api`.

## Scientific images

Landing cards use previews generated by Quantas rather than generic stock
images. Workflow and Result Explorer figures are built from frontend-neutral
specifications supplied by the backend.

## Local preferences

Theme, text scale, motion and density are stored in the browser and applied to
the document root. They are never written into scientific inputs, HDF5 results
or numerical exports.
